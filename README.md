# EaW Localisation Hub

Windows-first collaborative localisation environment for Equestria at War. The project is an alpha and is distributed under [GNU GPL version 2 only](LICENSE). See [CHANGELOG.md](CHANGELOG.md), [CONTRIBUTING.md](CONTRIBUTING.md), [SECURITY.md](SECURITY.md) and [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md) before contributing or redistributing binaries.

Clone the repository together with its native dependencies:

```powershell
git clone --recurse-submodules <repository-url>
cd EaWLocalisationHub
npm ci
npm test
```

## Возможности 0.8.7F1

- Desktop Agent автоматически находит обычный Git for Windows и встроенный Git из актуальной установки GitHub Desktop. Временная ошибка опроса Git или detached-состояние во время checkout больше не воспринимаются как ветка `unknown`: смена ветки начинается только после двух успешных одинаковых наблюдений, а при полном отсутствии Git выводится явная диагностическая ошибка.

- Legacy-плагин теперь полностью выключен по умолчанию: он не открывает панель, не рисует overlay и не перехватывает изменения или сохранение Notepad++. Команда `Открыть текущий файл в Review` при необходимости создаёт отдельное транспортное подключение к Agent без перехвата редактора, а `Включить интеграцию с Agent` сохраняет настройку и возвращает прежний функционал без перезапуска редактора.
- Кнопка `Git diff` в Review показывает локальную историю открытого файла вплоть до первого доступного commit и следует за переименованиями. Левую и правую версии можно выбрать независимо, включая текущий `HEAD`, поэтому одним diff можно увидеть весь путь файла от раннего commit до нынешнего состояния. Monaco скрывает неизменённые области; Git-команды выполняет только локальный Agent.
- Локальные и канонические Git-конфликты получили раздельные источники. При смене ветки прежние карточки сбрасываются во всех окнах Plugin/Review, физический текст нормализуется перед новым слиянием, а разрешение одного конфликта очищает его у всех локальных клиентов.

- Agent сохраняет физический формат окончаний строк Git worktree при материализации персонального файла. Для `text=auto` учитываются `.gitattributes`, `core.autocrlf` и `core.eol`; уже испорченный переходом `CRLF → LF` файл автоматически возвращается к ожидаемому Git-формату. Байтово неизменившийся файл больше не перезаписывается, поэтому GitHub Desktop не показывает ложное изменение без diff.

- Совместный Yjs-документ и рабочий Git-файл теперь разделены. Сервер хранит общую версию и независимые варианты каждого автора, а Agent материализует в физический файл только `Git HEAD + мои изменения`; чужие правки больше не могут случайно попасть в пользовательский commit. Управление материализацией открывается отдельной кнопкой «Локальный файл» и не занимает постоянную плашку над редактором.
- Переключатель Review показывает общую версию, чистый `Git HEAD`, собственный вариант и вариант каждого участника. Кнопки позволяют одним действием вернуть в рабочий файл Git либо пересобрать `Git + мои`, не публикуя такой откат в совместный документ. Разные варианты одного ключа сохраняются отдельно и показываются как конфликт, а не сливаются посимвольно.
- Устаревший mixed-author pre-commit hook из 0.8.5F2 больше не используется и безопасно удаляется Agent при запуске; существовавший до Hub пользовательский hook восстанавливается из сохранённой копии.

- Отключение аккаунта отделено от безвозвратного удаления. Отключение отзывает все сессии и закрывает совместные подключения, но сохраняет имя, роли, пароль и возможность позднее вернуть участника в команду.
- Роль `senior translator` получила отдельное окно «Управление командой»: senior может управлять другими неадминистративными аккаунтами, назначать в том числе новых senior translator и создавать приглашения. Собственный аккаунт и администраторы защищены сервером; роль `admin`, резервные копии и административные приглашения senior недоступны.
- Список приглашений показывает статус, выданные роли, срок действия, использованные и оставшиеся активации. Активный код можно отозвать, а завершённую запись удалить; открытый секрет по-прежнему показывается только один раз при создании.
- Щелчок по отмеченной правке или комментарию в Monaco прокручивает правую колонку к соответствующей карточке и временно подсвечивает её. При наложении диапазонов повторные щелчки перебирают карточки от самого узкого диапазона.

- Горячее переключение веток ждёт завершения checkout и стабилизации Git index, прежде чем читать файлы новой ветки. Review сразу переходит в read-only и обновляет подпись ветки; синхронизация буфера с уже записанным Git-файлом больше не помечает его изменённым и не запускает лишнее автосохранение.

- Сервер стал источником канонической Git-базы для основных комнат: он держит shallow sparse-кэш публичного `EaW-Team/equestria_dev`, загружает текст из ветки до подключения первого клиента и периодически обновляет активные ветки.
- Agent передаёт полный локальный `HEAD` и Git blob открытого файла. Сервер вычисляет затронутые localisation-файлы за весь диапазон пропущенных пользователем commit: изменения вне поддерживаемых папок не блокируют работу, а красная плашка и read-only появляются только у действительно изменившегося открытого `.yml` и снимаются после Pull через GitHub Desktop.
- Если перед блокировкой в локальном файле были незакоммиченные изменения, Agent сохраняет recovery-копию вне рабочего дерева. Сервер трёхсторонне объединяет изменения разных ключей, а совпавшие ключи открываются в локальном Monaco diff и разрешаются по одному.
- Переключение ветки теперь горячее: Agent временно переводит открытые документы в read-only, перечитывает файлы новой ветки и переподключает комнаты без перезапуска Notepad++, Review или Agent. Review также автоматически восстанавливает локальное соединение после перезапуска Agent.
- Совместная работа поддерживает все `.yml` внутри `localisation/russian`, `localisation/english`, `localisation/replace/russian` и `localisation/replace/english`. Для пакетной замены язык выбирается явно; поиск ключей охватывает как обычную, так и `replace`-локализацию выбранного языка. Английский оригинал также открывается из `localisation/replace/english`.

- Исправлена гонка при быстром закрытии, повторном открытии и переключении русских файлов: legacy-плагин сбрасывает готовность закрытого буфера и не отправляет `edit`/`snapshot` до нового `documentReady`. Agent безопасно отбрасывает запоздалые изменения уже закрытого или ещё не синхронизированного поколения документа вместо модального сообщения `Document is not synchronised yet`.
- Нижние секции левой панели Review больше не перекрываются: рабочая grid-строка ограничена высотой окна, секции не сжимаются поверх содержимого, а при недостатке места колонка прокручивается независимо от редактора.
- Обычные `Ctrl+Z` и `Ctrl+Y` в русских localisation-файлах снова принадлежат Notepad++. Совместные команды legacy-плагина оставлены на `Ctrl+Alt+Z` и `Ctrl+Alt+Y`; после входящего удалённого изменения плагин явно сбрасывает потенциально рассинхронизированную нативную историю. Review сохраняет компактный Google Docs-вид правки, но для многобуквенной замены расширяет диапазон до целого Unicode-слова, поэтому общие буквы не смешивают старый и новый варианты.
- Legacy-плагин завершает защищённый IPC-handshake до отправки `open`, `activate` и `cursor`, а при переподключении очищает устаревшую очередь. Desktop Agent безопасно игнорирует преждевременные события жизненного цикла документа (`activate`, `deactivate`, `cursor`, `close`), поэтому временная перестановка сообщений больше не вызывает модальное сообщение «The plugin has not opened».
- Desktop Agent больше не показывает ручное поле «Ветка»: workspace автоматически берётся из текущей Git-ветки. Явный `--workspace` сохранён только для лаборатории и диагностики.
- Административное окно требует повторно ввести пароль и получает отдельную десятиминутную admin-сессию только в памяти. Опасные операции требуют аутентификацию не старше двух минут; закрытие окна отзывает сессию. Для расписания резервных копий используется отдельный ограниченный backup-токен, который не даёт доступа к управлению пользователями.
- Кнопка «Отмена» закрывает создание тикета даже при пустом обязательном названии.
- Однобуквенные исправления остаются минимальными, а замены нескольких букв больше не сохраняют случайный общий хвост слова: Review показывает целую читаемую замену слова.
- Agent обрамляет снимок обсуждений и правок атомарной транзакцией. Review применяет его одной отрисовкой, переиспользует неизменившиеся карточки и обновляет только изменённые элементы вместо мигания полного списка.

- Legacy-плагин больше не загружает одно ядро процессора, когда Desktop Agent не запущен: повторное подключение к IPC использует прерываемую задержку вместо непрерывного цикла.
- «Изменить по ключам» принимает пакет записей `key:0 "текст"` и `key: "текст"`, позволяет выбрать русский или английский язык и показывает строгий предпросмотр. Меняются только значения найденных ключей в обычной и `replace`-локализации выбранного языка; отсутствующие и неоднозначные ключи блокируют применение.
- Replace All в режиме правок создаёт отдельные предложения для разнесённых замен; в обычном режиме применяется весь снимок файла.
- Принятые правки по умолчанию скрыты. Их можно показать, отменить и повторно принять, в том числе через `Ctrl+Z` и `Ctrl+Y`, пока изменённый фрагмент не был отредактирован ещё раз.
- Diff тикетов и истории вычисляется в Review, показывает изменённые области и ближайшие строки. Запись истории сравнивается со своим непосредственным предшественником.
- Английский оригинал открывается отдельным окном Review только для чтения. Прокрутка окон синхронизируется по ключам и может быть отключена.

## Совместные тикеты (0.8.5F1)

Review поддерживает изолированные совместные черновики – тикеты. Кнопка «Новый тикет» создаёт рабочую копию открытого файла от текущей Git-ветки и полного commit SHA. Тикет получает собственную Yjs-комнату: его текст, курсоры, выделения, брони, комментарии и предложения правок не смешиваются с основной версией файла или другими тикетами.

Переключатель под именем файла быстро открывает основную версию либо тикет текущего файла. Кнопка «Все тикеты» открывает общий каталог с поиском, статусами, архивом, редактированием названия и описания, списком до 50 файлов, суммарным diff по ключам и журналом событий. Завершённые тикеты можно архивировать, а команда безвозвратного удаления очищает метаданные, CRDT-документы и их историю.

«Обновить базу (rebase)» переносит изменения тикета с исходного commit SHA на текущий Git-коммит. «Применить к основной версии» трёхсторонне объединяет базовый Git-текст, основную совместную версию и тикет, затем проверяет серверные хэши всех файлов и обновляет основную CRDT-версию. Agent после этого заново получает персональную проекцию: чужой итог тикета не записывается напрямую в Git-файл участника. Конфликт любого ключа останавливает весь набор до записи и выставляет статус «Конфликт Git». Хаб по-прежнему не создаёт коммиты и не отправляет их в GitHub: итог проверяет и коммитит сам участник.

Кнопка «Английский оригинал» берёт ключ из строки под курсором и показывает точные совпадения из `localisation/english`. В основной версии используется текущий Git-коммит, а внутри тикета – зафиксированный базовый commit тикета.

Кнопка «История» в Review открывает список серверных версий текущего документа или тикета. Близкие по времени изменения одного автора объединяются в одну редакторскую сессию. Выбранная версия сравнивается с текущей через Monaco Diff Editor. Восстановление заменяет только текст и само записывается новой версией: прежняя история, комментарии, брони и предложения не удаляются. Перед применением сервер проверяет, что документ не изменился после открытия версии. Хранится не более 100 сжатых версий и не более 24 МиБ истории на комнату; история входит в зашифрованный резервный архив сервера.

Экспериментальная система совместного редактирования русской и английской локализации EaW через Notepad++. Это отдельный проект: он не изменяет устройство Git-репозитория мода и не отправляет коммиты от имени участников.

> **Notepad++-плагин переведён в режим Legacy.** Новые пользовательские функции развиваются только в приложении Review. Плагин сохраняется как совместимый вход из Notepad++ и будет обновляться лишь для исправления уязвимостей, критических ошибок и поломок совместимости с Agent/Review.

## Что уже работает

- синхронизация текста между несколькими пользователями через Yjs;
- отдельное совместное пространство для каждой Git-ветки;
- отслеживание `localisation/russian/**/*.yml`, `localisation/english/**/*.yml` и `localisation/replace/**/*.yml` внутри выбранной локальной копии репозитория;
- тихое игнорирование похожих `.yml` из других модов и папки самой игры без всплывающих ошибок Legacy-плагина;
- бессрочные мягкие брони, которые может создать или снять любой подключённый пользователь;
- устойчивые границы брони при вставке и удалении ключей внутри диапазона;
- отображение чужих курсоров и выделений текста в цветах участников, включая пустые строки и EOF; имя участника появляется только при наведении;
- встроенная док-панель со статусом соединения, цветным списком участников, переходом к их курсорам и управлением бронями;
- привязанные к тексту комментарии с ответами, закрытием, повторным открытием и удалением;
- предложения правок без немедленного изменения файла: обсуждение, принятие, отклонение и защита от применения к уже изменившемуся фрагменту;
- автоматическая материализация в локальный файл только Git-базы и изменений текущего пользователя;
- наблюдение за изменениями файлов после Pull в GitHub Desktop;
- сохранение базы трёхстороннего слияния вне Git-репозитория, включая Pull при выключенном Agent;
- трёхстороннее слияние изменений разных ключей и панель конфликтов одного ключа;
- горячее переподключение открытых документов при смене Git-ветки;
- отмена и повтор собственных совместных правок;
- сохранение документов, броней, комментариев и предложений сервером на диск;
- регистрация по одноразовым приглашениям и последующий вход по имени и отдельному паролю;
- несколько ролей на одном аккаунте: `admin`, `senior translator`, `translator`, `trainee-translator`, `translation-editor`;
- самостоятельная смена пароля, сильный одноразовый код восстановления и немедленный отзыв аккаунта или отдельной сессии;
- хранение пользовательского токена в Windows Credential Manager и запуск Desktop Agent из области уведомлений;
- окно администратора для выдачи приглашений, назначения ролей, разрешения нового кода восстановления, временного пароля, удаления доступа и создания резервной копии;
- переносимое Docker-развёртывание с ограничениями под VPS 1 ГБ RAM и опциональным Caddy/TLS;
- экспорт и восстановление серверного состояния; внешние копии шифруются AES-256-GCM;
- клиентский пакет с Node.js, Agent, плагином и установщиком;
- нативный x64-плагин Notepad++.

Плагин общается только с локальным Desktop Agent через Windows Named Pipe. Перед обменом командами стороны выполняют взаимную HMAC-проверку с локальным случайным секретом из Windows Credential Manager; стандартное имя pipe также выводится из этого секрета. Agent отвечает за путь репозитория, имя пользователя, ветку и соединение с сервером. GitHub Desktop продолжает использоваться участником самостоятельно; сервер не получает GitHub-токены и не делает коммиты.

## Быстрая проверка на одном компьютере

Нужны Windows x64, Notepad++ x64, Git и Node.js 22 или новее.

### Безопасная лаборатория в один клик

Для первой ручной проверки дважды щёлкните [Launch EaW Hub Prototype.cmd](Launch%20EaW%20Hub%20Prototype.cmd). Откроется launcher, который создаёт две тестовые копии файла, поднимает скрытые сервер и Agents и запускает два изолированных portable-экземпляра Notepad++. Оба экземпляра представляют разных переводчиков, но работают с одним совместным документом. Репозиторий `equestria_dev` при этом не используется и не изменяется.

Пошаговая проверка описана в [docs/LOCAL-LAB.md](docs/LOCAL-LAB.md).

### Ручной запуск защищённого сервера

```powershell
cd "C:\Users\AVX\Documents\eaw-localisation-hub"
npm ci
powershell -ExecutionPolicy Bypass -File .\scripts\bootstrap-zig.ps1
npm run check
```

В первом окне PowerShell запустить сервер:

```powershell
npm run server
```

При первом запуске сервер создаст одноразовый код администратора только в `data\prototype-server\bootstrap-invite.txt`, не выводя сам код в журнал. Дважды щёлкните `Launch EaW Hub Agent.cmd`, укажите `ws://127.0.0.1:3210`, локальный репозиторий и имя, вставьте код, придумайте отдельный пароль, нажмите «Регистрация по приглашению», затем «Запустить Agent».

После этого `Launch EaW Hub Admin.cmd` открывает административное управление, а `Launch EaW Hub Team Management.cmd` – управление командой для `senior translator`. Оба окна повторно запрашивают пароль и держат отдельную десятиминутную management-сессию только в памяти. Созданный там код переводчик вводит в окно Agent вместе с собственным новым паролем. Приглашение ограничено временем и числом активаций; его роли и остаток использований видны в списке. Выход, смена/сброс пароля, закрытие окна управления и ручной отзыв завершают соответствующие сессии раньше. Имя, которым подписываются курсоры и брони, берётся с сервера, поэтому подменить его параметром локального Agent нельзя.

Окно Agent показывает отдельные состояния сервера, локального процесса, сохранённого токена и совместимости версии/протокола. Проверка выполняется при открытии, затем каждые 15 секунд и по кнопке «Проверить сейчас». Для токена выполняется настоящий авторизованный запрос `/api/auth/me`, поэтому интерфейс различает действующий, отсутствующий и истёкший/отозванный токен. Рекомендуемая версия берётся из `/health`; проверка только уведомляет об обновлении и никогда самостоятельно не скачивает и не запускает EXE.

## Пароли, роли и приватность

Используйте для Hub уникальный пароль длиной не менее 12 символов, который нигде больше не применяется. В окне Agent это предупреждение показывается прямо над формой входа. Удалённый вход и запуск Agent разрешены только через `wss://`; незашифрованный `ws://` допустим лишь на этом же компьютере (`localhost`).

Сервер не шифрует пароль обратимым способом и не может показать его даже администратору. Он хранит только индивидуально посоленный проверочный хеш `scrypt` (`N=131072`, `r=8`, `p=1`, 32 байта). При регистрации клиент требует сохранить единственный 256-битный код восстановления в файл; сервер хранит только его HMAC-SHA-256 с отдельным pepper. Код одноразовый. После восстановления все прежние сессии завершаются, а Review показывает постоянную красную плашку до разрешения администратора и сохранения нового кода. Администратор сам код никогда не получает. Он также может установить временный пароль, который сервер заставляет заменить перед совместной работой.

Обычный пароль всё же кратковременно существует в памяти окна Agent и сервера и передаётся внутри TLS-соединения – обещать обратное для классического входа по паролю было бы технически неверно. Он не записывается в файлы и журналы. Клиентский токен хранится в Windows Credential Manager; пользователь того же Windows-аккаунта теоретически может его извлечь.

Hub не ведёт журнал входов и не сохраняет IP, User-Agent, имя устройства, время входа или историю удалённых аккаунтов/сессий. Caddy access log выключен. На сервере остаются только необходимые рабочие данные: отображаемое имя, роли, хеш пароля, хеши активных токенов/одноразовых кодов, CRDT-документы, действующие брони, комментарии и предложения правок с именами их авторов. В этих рабочих сущностях время создания не записывается. Из пяти переводческих ролей пока только `admin` влияет на разрешения; остальные уже являются многозначными метаданными для будущих правил.

При обновлении старые аккаунты и действующие токены сохраняются. Для существующих пользователей состояние recovery становится `setup_required`: они продолжают работать, но Review показывает красную плашку, пока каждый самостоятельно не выпустит и не сохранит свой первый код восстановления. Старые администраторские коды сброса удаляются при миграции и больше не принимаются.

Для диагностики Agent всё ещё можно запускать из консоли. Защищённому серверу обязательно нужен токен, а для взаимной проверки Agent и плагина – локальный секрет из Windows Credential Manager:

```powershell
. .\scripts\credential-store.ps1
$env:EAW_HUB_TOKEN = 'токен активированной сессии'
$env:EAW_HUB_IPC_SECRET = Get-OrCreate-EawHubIpcSecret
npm run agent -- --repo "C:\Users\AVX\Documents\Paradox Interactive\Hearts of Iron IV\mod\equestria_dev"
Remove-Item Env:EAW_HUB_TOKEN, Env:EAW_HUB_IPC_SECRET
```

По умолчанию Agent берёт имя текущей Git-ветки. Его можно задать явно: `--workspace general-dev`. Пользователи должны иметь одинаковое имя workspace, чтобы видеть один совместный документ. Базы слияния хранятся в `%LOCALAPPDATA%\EaWLocalisationHub`; для переносимой установки каталог можно задать через `--state "D:\EaW-Hub-State"`.

После сборки плагин находится в `dist\EawLocalisationHub`. Весь этот каталог надо поместить в каталог `plugins` используемой установки Notepad++:

```text
Notepad++\plugins\EawLocalisationHub\EawLocalisationHub.dll
```

Затем перезапустить Notepad++ и открыть файл из `localisation\russian`. Левая панель «Правки и комментарии» показывает состояние соединения, участников текущего файла, бессрочные брони, комментарии, предложения правок и конфликты Git. Пользователь отображается только в активной вкладке; фоновые вкладки продолжают синхронизироваться без зависшего курсора. Чужое выделение текста подсвечивается полупрозрачным цветом участника и обновляется вместе с его кареткой. Перед созданием брони можно выбрать любого зарегистрированного участника в поле «Бронь для». Диапазоны окрашиваются стабильным цветом владельца, а при наведении показывают владельца и, при делегировании, автора.

### Отдельное окно Review

Команда `Plugins → EaW Localisation Hub 0.8.7F1 → Открыть текущий файл в Review` открывает текущий файл в отдельном нативном окне на WebView2 с редактором Monaco. Его можно также запустить ярлыком «EaW Hub Review» и выбрать `.yml` вручную. Agent должен быть запущен и авторизован. Legacy-интеграция в Notepad++ при первой установке выключена, но команда открытия Review работает и в этом состоянии; включать интеграцию нужно только для возврата старой совместной панели и синхронизации внутри Notepad++.

Review является основным полнофункциональным клиентом. Слева находятся участники с переходом к курсору, безопасной загрузкой собственного аватара, бессрочные брони с назначением любому пользователю и конфликты Git с выбором совместного или внешнего варианта. Вверху доступны совместные Undo/Redo и переключатель «Редактирование / Правки». По умолчанию ввод сразу меняет совместный документ; в режиме «Правки» вставка, удаление или замена создаёт предложение и не затрагивает исходник до принятия. `Ctrl+Z` удаляет последнюю созданную таким образом правку, а `Ctrl+Y` восстанавливает её. Справа комментарии и предложения показаны разными по виду карточками напротив соответствующих строк: у каждого сообщения и предложения есть автор, аватар и дата; первое сообщение комментария выводится только один раз. Можно отвечать, закрывать, возвращать, удалять, принимать и отклонять. В замене новый текст выводится цветом автора непосредственно перед зачёркнутым исходным фрагментом, без стрелки; чистая вставка появляется в точке ввода, а удаление оставляет только зачёркнутый текст. В редакторе видны чужие каретки, выделения и цветные диапазоны броней с подсказкой владельца. Одновременно открытые Review и Legacy-плагин одного Agent публикуют одного участника и одну актуальную каретку, а не две копии пользователя. Изменения совместного документа безопасно материализуются в локальный файл, поэтому дальнейший commit и push по-прежнему выполняет сам участник через GitHub Desktop.

Аватар необязателен. Review принимает локальный PNG/JPEG/WebP до 10 МиБ, обрезает его до квадрата 96×96 и заново кодирует в WebP, поэтому исходный файл и его EXIF не отправляются на сервер. Сервер хранит только итоговый WebP до 16 КиБ, проверяет контейнер и размеры и не загружает изображения по внешним URL. Без аватара показываются инициалы пользователя.

WebView не получает пароль или серверный bearer-token. Agent поднимает отдельный сервер только на loopback-интерфейсе; случайные порт и локальный capability-token сохраняются в защищённом state-каталоге, чтобы уже открытое окно Review могло переподключиться после перезапуска Agent. Текущий discovery-файл запуска удаляется при завершении. Проверяются `Host`, `Origin` и точный путь файла, а навигация окна за пределы локального origin заблокирована.

В меню `Plugins → EaW Localisation Hub 0.8.5F1` команда «Оставить комментарий» создаёт ветку для выделенного диапазона либо текущей позиции. Двойной щелчок по комментарию переносит к диапазону и показывает обсуждение. Команда «Предложить правку» требует выделить заменяемый текст; новый вариант не меняет файл, пока любой подключённый участник не нажмёт «Принять». Исходный фрагмент зачёркивается цветом автора. В режиме «Карточки у текста» справа от видимого текста появляется привязанная к строке карточка автора с соединительной линией и сравнением `было → стало`; режим «Компактно» оставляет небольшой ghost рядом с диапазоном, а «Не показывать в тексте» убирает и ghost, и зачёркивание, сохраняя предложение в левой панели. При наведении компактный текст раскрывается подробнее. Overlay и карточки не входят в `.yml`, Yjs или Git. Комментарии и предложения в левой панели отсортированы по месту в файле и синхронизируются с видимой областью редактора. Если исходный фрагмент за это время изменился, сервер помечает предложение устаревшим и не применяет его. Любой авторизованный участник пока может отвечать, закрывать, принимать, отклонять и удалять эти рабочие сущности.

## Клиентский пакет

Собрать обычный Windows-инсталлер, который можно передать участнику:

```powershell
npm run build
```

Готовый файл находится в `dist\EaW-Localisation-Hub-Setup-0.8.7F1.exe`, рядом создаётся его контрольная сумма `.sha256`. Для сборки нужен Inno Setup 6 (`winget install --id JRSoftware.InnoSetup -e`). ZIP-пакет в `dist\EaW-Hub-Client-0.8.7F1.zip` остаётся запасным переносимым вариантом; для клиентского, deployer- и source-архивов также создаются отдельные файлы `.sha256`.

Инсталлер требует Notepad++ x64: Legacy-плагин является обязательным компонентом и не может быть снят флажком. Перед копированием DLL пользователь должен закрыть Notepad++. Также проверяется Microsoft Edge WebView2 Runtime; если его нет, мастер открывает официальный установщик Microsoft и продолжает только после появления Runtime. Agent, Review, встроенный Node.js и ярлыки устанавливаются в `Program Files`; системный Node.js участнику не нужен. Обновление использует тот же AppId и сохраняет настройки в `%LOCALAPPDATA%\EaWLocalisationHub` и токены в Windows Credential Manager. Автозапуск Agent и ярлык Review на рабочем столе предлагаются как необязательные пункты.

При удалении мастер отдельно спрашивает, удалять ли локальные настройки. Токены из Windows Credential Manager намеренно не удаляются вслепую: перед деинсталляцией пользователь должен выполнить «Выйти» для нужного сервера.

## VPS и резервные копии

Готовый комплект находится в [deploy](deploy). Сам Hub публикуется только на `127.0.0.1:3210`, а установленный на VPS Caddy предоставляет внешний адрес `wss://eawhub.mooo.com:10443` с автоматически обновляемым сертификатом Let's Encrypt. Порты Xray/Reality не менялись: отдельный TLS-порт позволяет одновременно использовать Hub напрямую, через VLESS или через AmneziaWG.

Для последующих обновлений предназначен отдельный Windows-deployer: `Launch EaW Hub Deployer.cmd`. Кнопка «Проверить VPS» показывает текущую серверную версию и SSH-отпечаток, который оператор должен подтвердить. После этого deployer собирает минимальный серверный архив без `.env`, резервных копий и пользовательских данных, проверяет SHA-256 на VPS, сохраняет предыдущий код, пересобирает Docker-контейнер и ждёт успешный `/health`. Если Docker Hub временно недоступен, совместимое обновление может быть собрано поверх уже работающего локального образа без остановки старого контейнера. Неудачный выпуск автоматически заменяется предыдущим. Пароль и парольная фраза ключа никогда не записываются в конфигурацию. Переносимый комплект собирается командой `npm run build:deployer`.

После входа администратор может нажать «Задать пароль копий» и «Создать копию сейчас». Файл `.eawhub.enc` появится в `Документы\EaW Hub Backups`; это и есть внешний бэкап на вашем часто включённом компьютере. Кнопка «Ежедневно в 03:00» создаёт задачу Windows с `StartWhenAvailable`: если ПК был выключен, пропущенный запуск будет выполнен после следующего входа. Пароль шифрования и отдельный токен только для резервного экспорта хранятся в Windows Credential Manager, а не в задаче или скрипте. Короткая интерактивная admin-сессия туда не записывается.

## Ветки и GitHub Desktop

Идентификатор совместного документа имеет вид `workspace:путь/файла`. Поэтому `general-dev` и ветка будущей страны не смешиваются. Agent наблюдает за открытыми файлами: после Pull изменения разных ключей автоматически объединяются с совместным документом и материализуются у подключённых участников. Последняя подтверждённая версия файла сохраняется отдельно для сочетания `репозиторий + ветка + путь`, поэтому тот же алгоритм работает после Pull при выключенном Agent.

При самом первом подключении уже разошедшихся локальной и серверной версий общей базы ещё нет. Agent намеренно не угадывает: в панели появляется конфликт «Начальная версия файла», где требуется один раз выбрать совместную версию или локальный файл Git.

Если один ключ изменён и в Git, и в совместной сессии, автосохранение этого файла приостанавливается. Конфликт появляется в панели. Двойной щелчок переносит к ключу; кнопка «Оставить текущий» сохраняет совместный вариант, а «Принять из Git» использует вариант с диска. Для ручного результата сначала отредактируйте ключ в Notepad++, затем выберите «Оставить текущий».

При переключении ветки Agent немедленно приостанавливает старый workspace, ждёт завершения файловой операции Git, перечитывает открытые localisation-файлы и подключает их к комнатам новой ветки. Перезапускать Agent, Notepad++ и Review не требуется. Если файла в новой ветке нет, он отмечается как недоступный и автоматически пробуется снова при следующем переключении; несохранённый буфер прежней ветки предварительно сохраняется в `git-recovery`.

## Ограничения и безопасность альфы

- это собственная авторизация альфа-версии: пока нет MFA, OAuth, журнала действий администратора и автоматической ротации обычных пользовательских сессий;
- встроенный сервер не завершает TLS; его нельзя выставлять в интернет напрямую или использовать через незашифрованный `ws://` вне localhost/VPN;
- восстановление резервной копии требует остановки сервера и выполняется оператором; пароль шифрования невозможно восстановить;
- задача внешнего копирования работает в сеансе администратора Windows: после долгого выключения она догонит запуск при следующем входе, но пока не отправляет отдельного уведомления о неудаче;
- поддерживается только Notepad++ x64;
- слияние Git выполняется по строкам ключей Paradox; одновременные сложные перестановки комментариев считаются конфликтом структуры файла;
- команда Undo из стандартного меню Notepad++ может не попасть в совместную историю; используйте `Ctrl+Z`, `Ctrl+Y` либо меню плагина;
- сервер назначает учётным записям разные стабильные цвета из палитры на 30 участников; это не настраиваемый профиль и не дополнительная персональная информация;
- это тестовый прототип, не предназначенный пока для рабочих переводов.

Подробности устройства находятся в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), текущие правила обмена – в [docs/PROTOCOL.md](docs/PROTOCOL.md), а порядок публикации релиза – в [docs/RELEASING.md](docs/RELEASING.md).
