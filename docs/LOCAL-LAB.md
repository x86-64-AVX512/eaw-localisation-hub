# Локальная лаборатория 0.8.7F5

Лабораторный сервер без `EAW_HUB_GITHUB_REPOSITORY` не обращается к GitHub и сохраняет начальный `canSeed`, чтобы искусственные ветки работали автономно. В production Compose канонический Git-источник включён по умолчанию.

Лаборатория предназначена для проверки сырой ранней бета-версии без рабочего репозитория EaW. Она создаёт внутри игнорируемого каталога `.tools/local-prototype`:

- два portable-экземпляра Notepad++;
- две независимые копии тестового файла локализации;
- общий каталог состояния сервера;
- два отдельных каталога локальных баз слияния Agents;
- журналы сервера и двух Desktop Agents.

## Запуск

1. Дважды щёлкните `Launch EaW Hub Prototype.cmd` в корне проекта.
2. Укажите имена двух тестовых участников. Они могут быть вымышленными.
3. Оставьте workspace `prototype-local` и нажмите «Запустить лабораторию».
4. В каждом Notepad++ выберите единственную команду `Plugins → EaW Localisation Hub 0.8.7F5 → Открыть текущий файл в Review`.
5. Дождитесь появления двух окон Review. Плагин не синхронизирует редакторы Notepad++ и не имеет настройки для включения прежней интеграции.

Флажок «Защищённый режим» включён по умолчанию. В этом режиме лаборатория поднимает сервер с обязательной авторизацией, создаёт две настоящие тестовые учётные записи и передаёт их сессионные токены Agents только через окружение дочерних процессов. Случайные тестовые пароли существуют лишь в памяти запускателя на время регистрации, не показываются и не записываются в файлы или журналы. При следующем защищённом запуске его отдельное тестовое состояние пересоздаётся; рабочие серверные данные и репозиторий мода не затрагиваются.

Откроются два окна Notepad++ с одинаковым относительным файлом, но из разных тестовых каталогов. После команды плагина совместная работа выполняется в двух отдельных окнах Review. Сервер и Agents работают в скрытом режиме. Кнопка «Папка журналов» открывает их журналы.

## Проверка совместной работы

Выполняйте действия только в открытых тестовых файлах.

1. Измените перевод одного ключа в первом Review. Изменение должно сразу появиться во втором Review.
2. Убедитесь, что слева в обоих Review показаны два участника. Поставьте разные курсоры, в том числе на пустую строку: чужая позиция должна отображаться тонкой цветной кареткой. Наведите на неё мышь – имя должно появиться; после ухода мыши подпись должна исчезнуть. Щёлкните имя удалённого участника – редактор должен перейти к его курсору и получить фокус.
3. В первом Review выберите второго участника в поле «Бронь для», выделите несколько строк и нажмите «Забронировать». Бронь должна появиться цветом выбранного владельца в обоих окнах; при наведении видны владелец и создатель.
4. Выделите перевод и нажмите «Комментарий». Во втором Review он должен появиться в панели и жёлтым диапазоном; ответьте на него, закройте и снова откройте. Щелчок по диапазону должен перейти к карточке и показать всю ветку.
5. Переключитесь в режим «Правки» и замените выделенный текст. Новый вариант пока не должен менять исходник. Во втором Review откройте карточку, ответьте и нажмите «Принять» – замена должна появиться в обоих окнах. Для проверки защиты создайте ещё одно предложение, измените исходный фрагмент другим участником и попробуйте принять: оно должно стать устаревшим без перезаписи текста.
6. Добавьте новый ключ внутрь брони – диапазон должен расшириться вместе с ним.
7. Удалите внутренний ключ – бронь должна сохраниться и уменьшиться.
8. Удалите начальный или конечный ключ – относительные границы должны остаться привязанными к окружающему тексту.
9. Нажмите `Ctrl+Z` в Review автора изменения. Должна отмениться его последняя совместная правка.
10. Поставьте курсор внутри брони и нажмите «Удалить под курсором». Удаление должно отобразиться у обоих участников.

## Остановка и восстановление

Нажмите «Остановить» в launcher. Если процесс ещё занят закрытием окон Review или Notepad++, дождитесь завершения и нажмите «Остановить» ещё раз. Серверные данные сохраняются отдельно, поэтому повторный запуск с тем же workspace восстанавливает совместное состояние.

Кнопка «Сбросить только тестовые данные» сначала сохраняет резервную копию предыдущего опыта в `.tools/local-prototype/backups`, затем удаляет две тестовые копии, тестовое состояние сервера и локальные базы слияния Agents и создаёт чистые файлы заново. Перед сбросом launcher требует подтверждение. Рабочий репозиторий мода не входит в список целей и не затрагивается.

Если два тестовых файла были сохранены в разном состоянии, следующий запуск специально останавливается и просит выполнить сброс. Это не даёт случайно выбрать одну из двух разошедшихся копий как исходную серверную версию.

## Командный запуск

Для проверки DLL выполните `npm run test:live-plugin`. Команда пересобирает плагин, загружает DLL нативным smoke-тестом и проверяет, что экспортирована ровно одна пользовательская команда открытия Review без сочетания клавиш или скрытого флажка включения.

GUI использует те же проверяемые сценарии:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local-prototype.ps1 `
  -User "Первый участник" -SecondUser "Второй участник"

powershell -ExecutionPolicy Bypass -File .\scripts\stop-local-prototype.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\reset-local-prototype.ps1
```

## Проверка канонической Git-версии

Launcher использует настоящий локальный bare-origin внутри `.tools/local-prototype/git-origin.git`. Обе тестовые копии являются отдельными Git-клонами, а сервер читает тот же origin через production-механизм канонической ветки. GitHub и Интернет для этого сценария не используются.

После запуска доступны три команды:

1. «Git: новый коммит на сервере» создаёт в локальном origin новый commit с тестовым файлом из `localisation/replace`. Через 1–2 секунды оба Review показывают жёлтое предупреждение и список изменённых localisation-файлов; только изменённый файл получает красную блокирующую плашку. Другой открытый файл той же ветки остаётся редактируемым.
2. «Обновить Git участника 1» выполняет безопасный fast-forward только первой тестовой копии. Первый Agent автоматически замечает новый `HEAD` и переподключает документы; второй остаётся устаревшим.
3. «Обновить Git участника 2» так же обновляет вторую копию. После этого у обоих участников исчезают предупреждения и блокировка изменённого файла.

Команды не изменяют рабочий репозиторий EaW. При сбросе лаборатории локальный origin и оба тестовых клона входят в подтверждённый сброс вместе с остальными данными лаборатории.
