# Развёртывание 0.8.6F4

F4 не меняет сетевой протокол или серверную схему данных. Сервер можно обновить до F4 для одинакового отображения версии клиента и VPS.

Схема авторизации 5 мигрирует существующие аккаунты и роль `senior-translator` автоматически. Аккаунты остаются включёнными, а старые активные приглашения сохраняются; секреты, пароли и серверные токены в комплект развёртывания не входят.

Compose по умолчанию задаёт `EAW_HUB_GITHUB_REPOSITORY` и `EAW_HUB_CANONICAL_REPOSITORY` равными `EaW-Team/equestria_dev`. Первая настройка проверяет base commit тикетов через GitHub API, вторая управляет shallow sparse-клонами внутри `hub-data` для `localisation/russian`, `localisation/english` и `localisation/replace`. Сервер сравнивает blob SHA каждого открытого файла, поэтому новый commit блокирует только реально изменённые `.yml`. Образ содержит Git; кэш восстанавливается автоматически. Для fork задайте своё `owner/repository` в `.env`.

Для VPS достаточно Docker Engine с Compose v2. Каталог `deploy` вместе с корнем проекта копируется на сервер.

Обычное обновление с Windows выполняется через `Launch EaW Hub Deployer.cmd`. Программа не включает `.env`, `deploy/backups` или данные Docker volume в загружаемый пакет, закрепляет SSH host key, проверяет SHA-256, создаёт откатную копию кода и требует успешный `/health`. При недоступном Docker Hub она умеет собрать совместимый выпуск поверх уже установленного серверного образа. Ручной способ ниже остаётся для первого развёртывания на пустой машине.

```sh
cd deploy
chmod +x install.sh backup.sh restore.sh
./install.sh
```

Без параметров сервер публикуется только на `127.0.0.1:3210`. Это подходящий режим для уже существующего reverse proxy либо SSH-туннеля. Первый администратор активирует код из Docker volume `/data/bootstrap-invite.txt`; сам сервер не печатает код в журнал. Установочный скрипт один раз читает файл и показывает код в текущем терминале владельца VPS.

Для отдельного домена отредактируйте `.env` и выполните `./install.sh --tls`. Встроенный Caddy занимает публичные порты 80/443. Если 443 уже занят VLESS, профиль `tls` включать нельзя: существующий reverse proxy должен направлять отдельный домен на `127.0.0.1:3210` с поддержкой WebSocket.

Ограничения рассчитаны на VPS с 1 ядром и 1 ГБ RAM: серверу доступно 384 МБ, Caddy — 128 МБ, журналы контейнеров ротируются. Проверки паролей scrypt выполняются последовательно и используют примерно 128 МБ памяти. Caddy access log отключён; сервер не сохраняет IP, User-Agent, имена устройств или историю входов. Данные находятся в именованном volume `hub-data`.

Резервная копия:

Ограниченный backup-токен выдаётся после повторного ввода пароля кнопкой расписания в Admin UI. Он разрешает только экспорт архива и не заменяет короткую интерактивную admin-сессию.

```sh
EAW_HUB_ADMIN_TOKEN='ограниченный backup-токен' \
EAW_HUB_BACKUP_PASSPHRASE='длинный отдельный пароль' \
./backup.sh
```

Файл шифруется AES-256-GCM до записи в `deploy/backups`. Храните пароль отдельно от VPS: без него копию восстановить нельзя.

Восстановление выполняется только после остановки сервера:

```sh
EAW_HUB_BACKUP_PASSPHRASE='тот же пароль' \
./restore.sh backups/eaw-hub-YYYYMMDD-HHMMSS.eawhub.enc
```

Скрипт восстановления сначала переносит прежнее состояние в recovery-каталог внутри volume.
